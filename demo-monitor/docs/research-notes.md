# Kalshi demo research notes

**Checked:** 2026-11-20 UTC. **Scope:** the initial repository was only `README.md`; this note records the official documentation checked before implementing the static dashboard. No market data or account values are copied into this repository.

## Verified facts and implementation choices

1. **Demo endpoints.** Kalshi's published API specification lists both demo REST base URLs supplied in the request: `https://external-api.demo.kalshi.co/trade-api/v2` and `https://demo-api.kalshi.co/trade-api/v2`. The browser client prefers the external host and tries the shared host if the request cannot be reached. Its WebSocket equivalents are documented separately. [Official OpenAPI specification](https://docs.kalshi.com/openapi.yaml) · [Quick Start: WebSockets](https://docs.kalshi.com/getting_started/quick_start_websockets)
2. **Public market data.** Kalshi documents unauthenticated reads for public market data, including series, events, markets, and an order book. The dashboard therefore reads only the demo market-data endpoints directly from the browser. A successful cross-origin browser request still depends on the endpoint/browser's CORS behavior; the app reports a connection error and leaves values blank if the browser cannot retrieve the feed. [Quick Start: Market Data](https://docs.kalshi.com/getting_started/quick_start_market_data)
3. **Official taxonomy.** Series expose `category`, `categories`, and `tags`; series categories can be multiple, and tags are subcategories. The site uses those returned fields rather than parsing tickers. The gas-price category mapping follows the official glossary example, which names series `KXAAAGASM`, categories `Economics` and `Commodities`, and tags `Oil and energy` and `Oil & Gas`. Crypto uses the exact `Crypto` category. Golf is included only when official Sports series metadata identifies Golf by tag/title. Elections uses official `Elections` metadata. “Culture” is presented as “Culture / entertainment”; mapping it to Kalshi's `Entertainment` discovery category is a site choice and is flagged for review, not claimed as a Kalshi-defined category. [Kalshi Glossary](https://docs.kalshi.com/getting_started/terms) · [Get Series List](https://docs.kalshi.com/api-reference/market/get-series-list) · [Get Tags for Series Categories](https://docs.kalshi.com/api-reference/search/get-tags-for-series-categories)
4. **Ranking dollar amount.** The regular market schema includes prices, top-of-book contract sizes, volume and open interest expressed as contract counts. Its `notional_value_dollars` field is not an event-level traded-dollar total. No official event-level dollar liquidity/turnover field was verified. The dashboard therefore sorts by a clearly labeled, site-defined **displayed top-of-book value**: for every open market in the event, add `YES bid price × YES bid contracts` and `YES ask price × YES ask contracts`. This is only the visible top quote on both sides, not full depth, traded volume, unique capital, or a Kalshi-defined event total. If any required price/size is absent or invalid, the dollar value stays blank and the row is flagged as incomplete. [Get Markets](https://docs.kalshi.com/api-reference/market/get-markets) · [Get Market](https://docs.kalshi.com/api-reference/market/get-market) · [Kalshi OpenAPI schema](https://docs.kalshi.com/openapi.yaml)
5. **Order-book depth.** Kalshi's public order-book endpoint returns YES and NO bids as price/count pairs. The arrays are sorted in ascending price order; only bids are returned. The complementary asks can be displayed as *implied* prices using the official binary-market relationship `1 - opposite-side bid`; counts are the corresponding opposite-side bid counts. The table labels these as implied and links to the raw endpoint. [Orderbook Responses](https://docs.kalshi.com/getting_started/orderbook_responses) · [Get Market Orderbook](https://docs.kalshi.com/api-reference/market/get-market-orderbook)
6. **Time series.** The REST candlestick endpoint documents intervals of 1, 60, or 1,440 minutes. It does not provide a historical seconds interval. The chart uses official candles where available and browser-observed REST snapshots for short “seconds” windows; those snapshots exist only while the page is open. This is not an unauthenticated WebSocket feed. [Get Market Candlesticks](https://docs.kalshi.com/api-reference/market/get-market-candlesticks) · [Quick Start: WebSockets](https://docs.kalshi.com/getting_started/quick_start_websockets)
7. **Resolution.** Market responses provide `status` and `result`; the schema allows `yes`, `no`, and `scalar` results. The site will display the returned result without translating scalar outcomes into yes/no. A market is treated as resolved only once the API reports its settled/finalized state; closed or determined is not treated as final. Historical markets beyond the current endpoint cutoff require the official historical endpoints. [Get Markets](https://docs.kalshi.com/api-reference/market/get-markets) · [Get Historical Markets](https://docs.kalshi.com/api-reference/historical/get-historical-markets) · [Historical Data](https://docs.kalshi.com/getting_started/historical_data)
8. **Portfolio and order access.** Balance, positions, fills, orders, and order creation are authenticated operations. Kalshi requires signed request headers with an API key; the WebSocket handshake is also authenticated. This repository contains no API key or private key. Because the deliverable is static GitHub Pages, the site does not ask for or store a private key in the browser and does not submit real demo orders. It offers a visibly labeled local paper-trade simulator only. [API Keys](https://docs.kalshi.com/getting_started/api_keys) · [Quick Start: Authenticated Requests](https://docs.kalshi.com/getting_started/quick_start_authenticated_requests) · [Get Balance](https://docs.kalshi.com/api-reference/portfolio/get-balance) · [Get Positions](https://docs.kalshi.com/api-reference/portfolio/get-positions) · [Get Fills](https://docs.kalshi.com/api-reference/portfolio/get-fills) · [Create Order (V2)](https://docs.kalshi.com/api-reference/orders/create-order-v2)
9. **GitHub Pages.** Before implementation, `gh api repos/karagemop466-tech/Demo3/pages` reported `status: built`, `source.branch: main`, `source.path: /`, and `build_type: legacy`. A later pre-PR read on 2026-11-20 still showed the same `main`/`/` legacy source but `status: building`; this establishes configuration, not that the new unmerged files are deployed. An attempt to switch the setting to Actions returned HTTP 403 (`Resource not accessible by integration`), so no GitHub-side setting was changed and no Pages Actions deployment workflow is included. Recheck the build and live URL after merging. [Configuring a publishing source](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) · [Pages REST API](https://docs.github.com/en/rest/pages/pages)

## Repository review

- Initial checkout contained only `README.md` (`# Demo3`), with no app, tests, data, source list, workflow, or prior coordination board.
- No existing application behavior or market/account data was available to verify.
- New API values are fetched live by the site; this note and the source catalog explain the schema and methodology rather than asserting current market values.
- The workspace's network policy did not permit validating live Kalshi demo account data during repository research. The site's runtime connection is therefore explicitly unverified until it succeeds in the browser. Empty/error states are intentional; no sample market rows or account balances are fabricated.

## Decisions intentionally not made

- Whether “highest dollar amount” should mean gross traded notional, open-interest value, top-of-book displayed value, full book depth, or some other measure. Current sort uses the documented site-defined top quote formula above and is marked for review.
- Whether “culture” should map to Entertainment and which exact election/golf subcategories to include. Current match rules use official series metadata and are inspectable on category pages.
- API-key custody, account/subaccount and exchange-index scope, portfolio history retention, and live-order risk limits. These require a secure authenticated service and owner decisions; none is guessed here.
