# Kalshi Demo Tracker (Demo3)

Collect, organize and analyze the **highest-dollar live events on Kalshi's demo exchange** in five
topics — **gas prices, elections, culture, crypto and golf** — track each event to its **yes/no
resolution**, execute and analyze **trades** (demo account or labeled paper mode), and work through
**questions and suggestions** before making decisions.

**Live site:** https://karagemop466-tech.github.io/Demo3/ (GitHub Pages, `main` / root)
- Coordination board: [COORDINATION.md](COORDINATION.md)
- Executive summary: [EXECUTIVE_SUMMARY.md](EXECUTIVE_SUMMARY.md) (site copy) and
  [docs/executive-summary.md](docs/executive-summary.md) (docs/ copy, session 4d10aedf)

## Verification rules

- Every table row links an official source (docs.kalshi.com or the exact demo-API request URL), or
  is left blank and flagged as unverified. Values are **never inferred**.
- Dollar figures derived as *contracts × last price* are labeled **estimates**.
- Demo-environment caveat (official): demo prices/behavior may not reflect real markets
  ([source](https://docs.kalshi.com/getting_started/demo_env)).

## Automated verified pipeline (session 4d10aedf)

A second, independent pipeline feeds the `docs/` site and provides **row-level verification** of
everything the collectors store (every stored row is re-fetched from the same official URL and
diffed; static fields and settlement results must match exactly, price drift is reported
separately — latest run: 725/725 checks, see `data/latest/verification_report.json`).

| Path | What it is |
|---|---|
| `scripts/collect_kalshi_data.py` | CI collector (official demo API; series-first topic selection; published deterministic classification rules — ticker regex → API tags → title regex → category) |
| `scripts/verify_rows.py` | Row-level re-verification against the live API (with settlement-transition retries) |
| `scripts/kalshi_client.py` | Authenticated demo-API client (RSA-PSS signing per official starter code) |
| `scripts/portfolio_pull.py` | Credential-gated portfolio/fills pull with automatic trade categorisation |
| `scripts/trade_runner.py` | Order placement for the demo account (dry-run default, size caps) |
| `scripts/build_site.py` | Generates the HTML page shells in `docs/` |
| `scripts/verify_site.py` | Checks sources, internal links, JS syntax, render-hook coverage |
| `.github/workflows/kalshi-data.yml` | Twice-hourly collection + verification + data commit |
| `.github/workflows/kalshi-portfolio.yml` | Hourly portfolio pull (activates when repo secrets exist) |
| `data/latest/` | Pipeline snapshots (markets, events, top-dollar ranking, orderbooks, candles, trades, resolutions, portfolio status, verification report). Every row carries `source_url`. |
| `data/history/` | Rolling history: price samples and the accumulated resolution log (trimmed to 20,000 lines) |

Portfolio and order endpoints require a demo-account API key (never stored in this repo). To
activate: add repository secrets `KALSHI_KEY_ID` and `KALSHI_PRIVATE_KEY`, and the hourly
workflow fills the site's portfolio tables automatically. No credentials are stored in this repo,
and no values are ever inferred — missing data is shown blank and flagged.

## Data sources

Kalshi documentation at https://docs.kalshi.com (the `llms.txt` index lists every page) and the
**demo** Kalshi Trade API at
[`https://external-api.demo.kalshi.co/trade-api/v2`](https://external-api.demo.kalshi.co/trade-api/v2)
(also supported: `https://demo-api.kalshi.co/trade-api/v2`) per
[API Environments and Endpoints](https://docs.kalshi.com/getting_started/api_environments).
The live dashboard calls the public endpoints from the browser (market data needs no key); if the
browser cannot reach them, the page says so and shows the pipeline/verified snapshots instead.
