Methodology

How every number on the dashboard is produced — and its limits. Nothing here is inferred beyond the stated formulas.

1 · Topic discovery

StepDetailSource
FetchGET /series returns all series with title, tags, categories. Get Series List
ClassifyKeyword match (case-insensitive) against title + ticker + tags + categories + primary category. First topic with a match wins; the matched keyword is shown in the discovery table for audit. Dashboard code (assets/app.js) — transparent, editable.source
Why not ?category=GET /series?category= requires exact, case-sensitive category values that are not enumerated in the docs, and GET /events has no category filter (event category deprecated). Keyword discovery avoids guessing category strings. Get Series List, Get Events
LimitKeyword matching can miss series (e.g. a golf series whose title avoids “golf”) or over-match (e.g. “vote” in a non-election title). The manual series override on the dashboard covers gaps. See Open Questions. —source

2 · “Highest dollar amount” ranking

MetricFormulaWhat the API actually reportsSource
Estimated $ volumevolume_fp × last_price_dollars volume_fp = lifetime contracts traded; last_price_dollars = last trade price ($0–$1). Get Markets
Estimated $ open interestopen_interest_fp × last_price_dollars open_interest_fp = outstanding contracts. Get Markets
RankingSort by estimated $ volume desc, then estimated $ OI desc. Top 25 shown. Dashboard code.—source
Limitation: the API does not report a dollar-volume field per market. Contracts × last price is an estimate — it overstates value for markets whose volume accumulated at higher prices and understates for the reverse. Treat the ranking as a screening tool, not a precise dollar figure. See Open Questions Q3.

6 · Live swing alerts & high-ROI screen

The dashboard’s card 6 (assets/alerts.js) implements the brief’s alerting requirement: a sudden move of the tracked YES price by ≥ $0.10 (10 cents) in either direction posts an alert into two simplified scrolling chats — All events and High-ROI model picks — and draws ▲/▼ markers on the price chart with a per-market jump list.

ItemDefinitionSource
Watch setUp to 80 open markets from the current scan, ranked by the site’s estimated dollar volume (card 1); selected market and markets with a recent alert are always included. Coverage equals scan coverage — disclosed, not exhaustive. Get Markets
Tracked priceYES bid/ask mid when both quotes exist (yes_bid_dollars, yes_ask_dollars), otherwise the last trade (last_price_dollars). Dollar-string fields; legacy cent integers accepted as fallback. Get Markets fields
Swing ruleFire when |price(now) − baseline| ≥ 0.10, where the baseline is the oldest sample within 150 s that is ≥ 20 s old; a ≥ 0.10 move against the immediately previous sample also fires. Cooldown: one alert per market and direction per 5 minutes (dedupe bucket). Poll cadence 10 s via GET /markets?tickers=… (comma-separated; official: as the only filter it returns every match in one response). Get Markets paging rules
Latency disclosureExchange responses are cached — prices, sizes and status can lag the exchange by several seconds (official Get Markets note); alert detection is therefore best-effort, not exchange-grade. The WebSocket API offers push data but requires signed handshake headers browsers cannot attach (board item I-13), so this layer polls. WebSocket connection
High-ROI screen (heuristic)A swing alert becomes a “pick” only if all five rules pass: HR-1 two-sided book (bid>0 and ask>0) · HR-1b ask>bid · HR-2 quoted spread ≤ $0.10 · HR-3 volume_fp ≥ 1 (a trade exists) · HR-4 post-move price in [0.02, 0.98]. This is a liquidity/decidability screen, not validated alpha — no expectancy backtest has been run against it; treat as a starting filter only. Get Markets fields
Causation linksEach jump links (a) its exact API row and (b) all markets of the same event via GET /markets?event_ticker=… — both verifiable sources. A third link, “news search?”, is a query generated from the market title at click time so a trader can look for a possible cause. The API exposes no news/attribution field: causation is never asserted, and the link is labelled unverified in the UI. Get Markets event_ticker
Resolution noticesTracked markets that transition to closed/determined/finalized with result “yes” or “no” post a system message to the All-events chat (result enum + settlement doc). Tracking runs while the page is open, matching card 3’s resolution logger. Market Settlement
PersistenceAlert log + dedupe memory live in this browser’s localStorage (cap 300, exportable as JSON). Nothing is sent to Kalshi; no credentials are used (public market-data endpoints only). Demo environment
