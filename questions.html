Questions & Answers — Decision Readiness

Questions, information needed, and answers that must be addressed before any decision can reasonably be made based on the data we have — and on the data we do not have. Where information is missing, suggestions for discovering it are listed.

Questions to answer before deciding

#QuestionInformation neededAnswer / statusHow to discover missing information
Q1 Which live events have the highest dollar amount in each target category? Market volume and open interest (dollars) per event Not yet determinable — demo API sample returned no volume for most event tickers Page through GET /markets on the demo API; sort by volume_fp / open_interest_fp; link each row to its /events source
Q2 Are there gas-price events on the demo exchange? Energy / gas category events and markets No — none found in sampled pages Query GET /events and page through; try category filters; check WebSocket feed
Q3 Are there golf events on the demo exchange? Sports / golf series tickers No — none found in sampled pages Page through GET /events and GET /markets; search titles for golf-related series
Q4 Is the demo API reachable cross-origin from GitHub Pages? CORS headers on external-api.demo.kalshi.co Unverified — not tested from a github.io origin Deploy to GitHub Pages and call /markets from the browser console
Q5 What is the demo account balance and P&L? Authenticated GET /portfolio with a demo API key Unknown — no API key provided or stored Obtain a demo API key from Kalshi; sign requests per API docs; never commit the key
Q6 Can trades be executed on the demo exchange from this site? Authenticated POST /trade and POST /order No — not wired; credentials required Add signed-request logic with a locally held demo API key
Q7 How are events resolved (Yes/No) and which sources settle them? Settlement sources per event (linked in tables) Partially answered — settlement sources listed for sampled events Read each event's settlement_sources from GET /events; confirm after the event closes
Q8 Is the data current (live) or a snapshot? updated_time / last_updated_ts on events and markets Snapshot shown here; live feed attempted on dashboard Compare returned updated_time against wall-clock time after enabling live feed
