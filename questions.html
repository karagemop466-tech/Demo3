Answers delivered by automation Session 3b5e95bd — updated from live collector runs, 2026-11-20

The scheduled collector (collector/collect.py, GitHub Actions every 10 minutes) now answers several questions that were open when this register was written. Every answer below is backed by a live demo-API response committed under data/; source links point at the exact endpoint queried.

#Question (from register above)Answer / current statusEvidence & source
A1 Q1 — Which live events have the highest dollar amount per category? Answered per run: events are ranked by estimated dollar volume (Σ contracts × last price; the API reports contracts and prices, not dollars, so the figure is labeled an estimate). Current leaders in the latest snapshot are listed on the Data Tracking page. Data Tracking page; GET /events?status=open&with_nested_markets=true
A2 Q2 — Are there gas-price events on the demo exchange? No live gas-price events existed at collection time (2026-11-20). The collector therefore also sweeps settled markets of the officially documented gas series (KXAAAGASM) and every tracked series, so gas resolutions (yes/no) are tracked even when nothing is live. If the demo exchange lists no settled gas markets either, the topic shows blank/flagged rather than an invented value. Kalshi fee schedule (series KXAAAGASM); GET /markets?series_ticker=KXAAAGASM&status=settled; collector log data/meta.json
A3 Can the browser fetch the demo API directly (CORS)? Yes — verified live: the demo API returns Access-Control-Allow-Origin: https://karagemop466-tech.github.io for this site's origin, so live in-browser dashboards and snapshot rendering both work. data/cors_test.json (probe recorded each run, sent with Origin header)
A4 Do the demo market objects report volume/liquidity fields? Yes — volume_fp, volume_24h_fp, open_interest_fp, yes_bid_size_fp, yes_ask_size_fp (fixed-point strings) plus dollar-denominated bid/ask/last. Contract counts at each price come from the orderbook endpoint (bids-only book; a YES bid at $X equals a NO ask at 1−$X). docs.kalshi.com quick start; GET /markets (live sample); orderbook semantics
A5 How are events tracked until resolution? Every in-scope live event enters data/tracked.json on first sighting and is re-polled on later runs; once all its markets are settled the outcome side (YES/NO), winning markets, and settlement sources are written to data/resolutions.json and shown on the Data Tracking page. market settlement (result = yes/no, $1 per winning contract); Data Tracking → Resolution tracking
A6 What can and cannot be verified about the demo portfolio and trading? Cannot be verified yet: the pipeline (signed requests, portfolio snapshot, order placement, PnL on settlement) is implemented and offline-tested, but no demo-account credentials exist in this environment, so no portfolio or trade rows are produced. Nothing was inferred; see Flagged for Review item F9. demo.kalshi.co (account sign-up requires human registration); signing spec; Flagged F9
