Kalshi demo — market analytics, live dashboard and trade tracking

This site reads the Kalshi demo Trade API (https://external-api.demo.kalshi.co/trade-api/v2) and publishes only what that API actually returns. It ranks the highest-dollar live events in five topics — gas prices, elections, culture, crypto, golf — tracks each one until it resolves, records the yes/no outcome, charts price movement with a selectable time axis, shows contracts resting at each price, and turns every fill into a categorised, strategy-tagged ledger. Nothing here is estimated: a value with no source is shown as an em-dash and listed on Flagged for Review.

Read this first — four constraints that shape everything
  1. “Dollar amount” does not exist as a field. Kalshi reports volume_fp in contracts. We compute dollars from the tape and label the formula on every table. source
  2. Second-level history does not exist. Candles start at 1 minute, so a “seconds” axis is built by sampling in the browser and is labelled client-sampled. source
  3. The order book is bids-only by design. The ask side is derived as $1.00 − best opposite bid. source
  4. WebSocket needs a signed handshake, which a browser cannot perform — live streaming therefore requires the local bridge. source

How to reproduce or extend

Refresh the dataset (needs network egress to kalshi.co) 
python3 scripts/collect.py --window-minutes 30 --pages 6 --top 40
python3 scripts/aggregate_capture.py --write   # re-derive dollar volume
python3 scripts/verify_site.py                # blank-cell + link audit
True live mode (bypasses CORS, adds signing) 
python3 scripts/dev_server.py --port 8081
# then open http://localhost:8081/dashboard.html?mode=bridge

The bridge proxies public reads same-origin; with KALSHI_API_KEY_ID + KALSHI_PRIVATE_KEY_PEM_PATH it also signs /portfolio/* and the WebSocket handshake.
