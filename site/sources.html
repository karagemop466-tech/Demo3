Rendered from data/sources.json, the registry scripts/verify_site.py audits. Each entry records the URL, what it establishes, which file in this repository consumes it, and whether it was verified. Anything not verified is marked unverified with a reason, and no published number rests on it.

The verification rule, stated once

Official

A host Kalshi controls: docs.kalshi.com, kalshi.com, *.kalshi.co. Enough to establish how an endpoint behaves, and — for a market field — what it means.

API response, archived

A read this project made and stored verbatim under data/. Enough to establish what the value was at that instant, and nothing more.

Third-party

Never verification. Either it is a source Kalshi itself names inside settlement_sources — recorded as “what Kalshi points at” — or it does not appear at all.

What could not be checked from this environment. The sandbox has no network egress to kalshi.co, so shell curl against the demo API fails even though the endpoints work; the docs site and the API itself were reached through the agent's fetch path, and those responses are archived in data/. Links here open the live originals — if one is blank in your browser, that is a network path difference, not a dead reference. See FLAG-12.
