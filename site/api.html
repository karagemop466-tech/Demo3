Field semantics that change the numbers

Fixed-point strings

Prices and sizes are decimal strings, not floats: "count_fp":"1851.85", "yes_price_dollars":"0.0040". Requests accept 0–2 decimal places for count and 2–4 for price; responses carry up to 6. Parsing with float() then re-serialising is how this project avoids cent-rounding drift; scripts/kalshi_api.py:fp() is the only place conversion happens. source

Money units

Balance-style fields are integer cents (balance) with a balance_dollars string sibling; portfolio_value has no documented dollars sibling, so the dollars figure on the portfolio page is cents/100 and labelled derived. source

Timestamps

Response fields are ISO-8601 UTC strings; request filters (min_ts, max_ts, min_close_ts, start_ts/end_ts) are integer seconds. Milliseconds there are a 400. source

Pagination

GET /markets/trades takes limit 1–1000 (default 100) and a cursor; an undecodable cursor silently returns page one, so a loop must compare content, not just cursor emptiness. GET /series has no pagination at all — limit is accepted and ignored. source

Sharding

Four exchange indexes exist in demo, all trading_active. Markets are spread across them (crypto on index 2, one golf/tennis series on 3, most on 0), and writes need exchange_index + market_ticker to route a cancel correctly. Rate-limit write buckets are per shard. source

Rate limits

Token bucket, default 10 tokens per request, separate Read and Write budgets, 3-second burst window at Basic/Advanced; 429 comes back as {"error":{"code":"too_many_requests"}} with no Retry-After, so the client backs off from X-RateLimit-* instead. Unauthenticated traffic has its own undocumented limits. source

Authentication, exactly as specified

message   = f"{timestamp_ms}{METHOD}{path_including_prefix}"      # e.g. "1731234567890GET/trade-api/v2/portfolio/balance"
signature = base64( RSA-PSS-SHA256(sign, message, salt_length=digest_length) )   # or Ed25519, which signs the raw message
headers   = {"KALSHI-ACCESS-KEY": key_id, "KALSHI-ACCESS-TIMESTAMP": str(timestamp_ms), "KALSHI-ACCESS-SIGNATURE": signature}
websocket = message for the handshake is f"{timestamp_ms}GET/trade-api/ws/v2"      # no query string, prefix included

Implemented in scripts/kalshi_api.py:Signer with an openssl CLI fallback so the repo works without the cryptography wheel. Query parameters are excluded from the signed string, which is why ?limit=… never appears in a signature. source · key format
