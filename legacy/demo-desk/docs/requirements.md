# Kalshi Demo Dashboard — executive summary and decision register

Verification date: 2026-11-20 UTC. This repository began as a one-line README (`README.md:1`, `# Demo3`) with no site, source data, tests, or deployment configuration. All confirmed product/API facts below are linked to Kalshi's official developer documentation or Help Center. No market values have been hard-coded.

## Executive summary

The repository is being shaped into a static GitHub Pages dashboard for Kalshi's **demo** environment. Its read-only market screens use the official demo REST API for events, market quotes, order books, and market results. The dashboard is intended to cover only the requested topic groups: gas prices, elections, culture, crypto, and golf. Topic grouping is an explicitly disclosed dashboard filter based on official event fields and narrow text matches; it is not presented as Kalshi's own taxonomy.

Several requested features cannot responsibly be switched on in a static public site without account access and secure infrastructure:

1. Kalshi's documented account, positions, fills, settlements, and order endpoints require signed API-key requests. A WebSocket connection also requires a signed API-key handshake even for public market-data channels. No demo credentials or account access were present in this repository/session. [API Keys](https://docs.kalshi.com/getting_started/api_keys) · [WebSocket Connection](https://docs.kalshi.com/websockets/websocket-connection)
2. The documented public REST market schemas expose contract counts for volume/open interest, not the WebSocket ticker's `dollar_volume` / `dollar_open_interest` fields. Since the latter require an authenticated WebSocket, the site must leave exact dollar rankings blank rather than relabel contract counts as dollars. [Get Markets](https://docs.kalshi.com/api-reference/market/get-markets) · [Market Ticker WebSocket](https://docs.kalshi.com/websockets/market-ticker)
3. GitHub Pages is static hosting; a private key must not be placed in its browser JavaScript. Portfolio access and order execution therefore remain disabled until a separately secured server-side signing service is provisioned. A signed order endpoint is documented, but no order is sent by this project. [Create Order (V2)](https://docs.kalshi.com/api-reference/orders/create-order-v2) · [API Keys](https://docs.kalshi.com/getting_started/api_keys)
4. Kalshi's official candlestick endpoint supports 1-minute, 1-hour, and 1-day bars. Seconds-scale graph samples can only be labeled as local polling observations, not exchange-provided second candles. [Get Market Candlesticks](https://docs.kalshi.com/api-reference/market/get-market-candlesticks)

**Safe operating definition:** use demo-only public REST for live market quotes and visible order-book levels; consider a market YES/NO-resolved only when its status is `finalized` and its result is `yes` or `no`; label everything else according to its actual lifecycle state. The official lifecycle guide distinguishes closed/determined from finalized. [Market Lifecycle](https://docs.kalshi.com/getting_started/market_lifecycle)
